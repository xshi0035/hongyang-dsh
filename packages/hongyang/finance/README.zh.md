# @deepseek-ai/dsh-hy-finance

[English](README.md) | 中文

## 概述

财务用户可以导入商户应收、银行流水与支付平台对账单，审阅收款分配和收入日报表。本包支持报表与金蝶凭证草稿导出，并提供应收查询。每项金额、税额和拆分均由确定性 provider 代码计算。客户数据对账与钉钉卡片验收仍未完成；登记成功不等于已与银行流水对账。

<a id="use-this-package"></a>
## 使用本包

弘阳 Web profile 挂载本财务插件。通过其设置与会话工具导入文件、审阅待认领款项、生成报表及导出凭证草稿。[当前交接文档](../../../docs/hongyang/CLAUDE_HANDOFF_2026-09-14.zh.md) 记录已验证的启动方式与验收状态。

### 配置

[配置 schema](src/config.ts) 定义可接受的设置。数据库路径为空时在 `DSH_HOME` 下解析；更改数据库路径需要重启宿主。

| 字段 | 默认值 | 含义 |
|---|---|---|
| `dbPath` | `$DSH_HOME/hongyang/finance.db` | 配置字段为空时采用的 SQLite 数据库 |
| `autoOpenCards` | `true` | 审阅卡片默认展开 |
| `compareToleranceCents` | `1` | 比对金额容差，单位为分 |
| `outputTaxSubject13` / `outputTaxSubject3` | 空 | 已确认电费/水费销项税科目的可选覆盖值 |
| `companyName` | 衡阳诚远商业管理有限公司 | 付款图片校验期望的收款方 |

销项税覆盖值为空时使用[费项规则](src/rules/fee-types.ts) 中已确认的科目：13% 电费采用 `2221.01.02.13`，3% 水费采用 `2221.01.02.03`。其他费项缺少科目仍会阻止生成完整凭证。

### 费项审核与付款冲正

在待审核付款中打开费项核对，增加费项金额、可选的完整账期并填写分配依据。批准前服务端要求正整数分金额合计等于原付款金额。批准保留原始证据与审核拆分，内容冲突的重试失败。已入账的钉钉登记可以从付款日期列表中填写冲正日期及原因后全额冲正。原单保留，关联的负数分配恢复对应应收余额。有效凭证草稿在撤回前阻止冲正。该操作仅修改本系统登记，不执行退款，也不冲销外部已过账凭证。同一交易单号继续保留，重新登记前需要人工复核。

### 选择收款制证

在工作台选择已认领收款，再生成凭证草稿。清单保留全日已认领、已生成草稿、待制证和尚未认领统计；未认领 POS 款项不能靠合计金额凑选。UONE 代收款使用 `uone_collection` 和已确认的负债科目 `2241.12`，不记收入或销项税。`finance_voucher` 工具先列出收款键，再接受明确选择，不默认选择全天。草稿占用所选收款；相同请求返回同一草稿。填写原因撤回草稿后，收款返回待制证，原证据保留。生成草稿不代表过账。

停车备注中的有效单一业务日（`@YYYYMMDD#停车费`）决定日报与凭证日期；原到账时间不变，日报行注明业务日归属待复核。日期范围或无效日期暂保留到账日，等待单独的分配规则。POS 明确停车备注按停车费处理，不推断签约商户。人工分配更正保存修改前后记录及依据，拒绝过期分配；已被有效草稿占用的收款不能直接更正。参见[选择制证与更正决策](../../../.agents/notes/implemented/architecture/2026-09-15-hongyang-selected-vouchers.zh.md)。

<a id="understand-the-implementation"></a>
## 理解实现

<details>
<summary>实现细节</summary>

[财务服务](src/service/finance-service.ts) 持有 SQLite 连接，将操作委派给 provider 模块。[工具](src/tools/plugin.ts) 将这些操作提供给 agent；[技能](src/skills/plugin.ts) 按需提供业务口径。[客户端视图](src/client/index.ts) 展示结构化结果和审阅动作。数据库是权威数据：schema 第 2–4 版通过事务升级到第 5 版，保存审核、分配更正、凭证选择和付款冲正记录；未知版本拒绝启动。

日报表比对在配对行后检查费项列；小计相等不代表分配相同。凭证导出的原币、借方与贷方金额单位均为元。显式指定账期的分配仅关联同账期应收。

工作台跨记账日期展示钉钉提交单。提交仅保存证据和操作记录，不创建流水或分摊；经认证的 `POST /api/hy-finance/payment/review` 批准或驳回选中的单据。批准重新校验草稿，并原子保存财务记录、决定及审核日志。重复的相同决定返回已有结果；冲突决定失败。付款日期在提交时固定。审批 provider 不暴露为 agent 工具。面板在打开及浏览器重新获得焦点时刷新。参见[审批决策](../../../.agents/notes/implemented/architecture/2026-09-15-hongyang-workbench-approval.zh.md)。

非空的钉钉交易单号与已有流水和待审核单作精确比较。提交和批准时的检查在 SQLite 写事务内执行。工作台为旧队列中的重复单读取实时提示，禁用批准按钮并保留驳回；服务端批准入口也会执行同样检查。已驳回的单据不占用交易单号。缺少单号时，不根据相同金额、商户或日期猜测重复。 重复提示区分最近一次申请被驳回与此前登记仍有效。原登记时间取自登记审核日志，缺失时使用分摊创建时间；未知时省略，不从付款日期推断。

</details>

## 模型体验

### 财务身份与技能

#### 模型看到什么

根插件提供弘阳身份，并要求模型用财务工具完成算术。技能目录提供 `hy-finance`、`hy-daily-report` 和 `hy-voucher`；正文仅在请求时加载。这些文本描述公司主体、收款渠道、费项、税率规则、报表与凭证。

#### Token 影响

身份文本与技能描述增加提示词 token；按需加载的技能正文增加任务相关上下文。工具结果增加结构化财务记录，并以元展示格式化金额。具体 token 用量取决于任务与导入行数，本次修订未做测量。

#### KV Cache 影响

稳定的身份与技能文本可以在请求间保持不变。导入记录、查询结果与工具历史随任务变化；本包不控制也不保证提供方缓存复用。

## 已知限制与待办

<a id="known-limitations-and-deferred-work"></a>

- 图片 provider 写入前必须验证收款方、正数金额和有效支付时间，并保留交易单号。不完整证据不写入；未解析商户或费项需要确认。钉钉图片草稿使用只读预览，并在确认时重新校验证据和所选商户；文字金额冲突会被拒绝且不写入。Web 图片登记和截图真机验收仍未完成。
- 部分费项没有已确认的预收科目。即使电费和水费销项税科目已配置，包含未决映射的凭证仍为草稿。
- 工作台尚未提供部分冲正、银行/POS 登记冲正或已冲正交易单号重新登记。
- 台账比对依赖客户日期与铺位号填写规范；缺少日期的行无法匹配。
- 自动费项分配根据简短付款备注推断意图。有证据的人工纠正不代表自动认领验收通过。
- 客户完整样本对账与真实卡片确认仍需验收；本地测试不能证明生产集成可用。
