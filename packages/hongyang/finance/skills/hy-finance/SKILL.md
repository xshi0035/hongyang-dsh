# 弘阳广场财务口径

## 主体与账户

- 法人主体：衡阳诚远商业管理有限公司。所有收款的收款方都应是它；付款截图上收款方不是它时要提醒用户。
- 收款账户与来源枚举（与日报表"收款来源"列一致）：银行转账2038（建行主账户，科目 1002.02）、银行转账2035（建行副账户）、平安银行（停车系统结算）、POS收款（银联商务日结，科目 1012.08）、企业微信706（微信商户号 1693395706，电费充值小程序）、企业微信380（微信商户号 1723333380，停车费）。

## 费项、税率、科目

日报表 22 个金额列按此顺序：租金 9% (2203.01.01)、经营服务费 6% (2203.01.02)、宣传服务费-推广 6% (2203.01.03)、多经收入-仓库 6%、多经收入-广告位 6%、固定点位-服务费收入 6%、临时点位收入-服务费收入 6%、后付水费 3%、后付电费 13%、预付电费 13%、装修管理费 6% (2203.06)、垃圾清运费 6% (2203.11)、证件工本费 6% (2203.05)、停车费 6%、诚意金 无税 (2241.02)、装修押金 无税、保证金 无税 (2241.05)、暂收款 无税 (2203.01.05)、消防泄水费、其他、购券。

销项税科目：6% → 2221.01.02.06，9% → 2221.01.02.09；13% 与 3% 的科目待客户确认，未确认前 finance_status 会列出。税额 = round(含税 ÷ (1+税率) × 税率, 2)，由工具计算。

## 摘要模板

- 费项：`收到商户{费项}{期间}-{铺位号}&{商户名}`，期间写作 `2026.4.1-2026.4.30`。
- 暂收款：`收到暂收款项-{付款人}`。

## 收款渠道识别（建行流水对方户名）

- 含"财付通" → 微信日结。备注 `MMDD_商户号`，到账金额 = 该商户号前一日微信对账单"应结订单金额 − 手续费"之和。
- 含"银联商务" → POS 日结。备注 `MMDD-MMDD费x元`，到账金额 = 前一日 POS 对账单"清算金额"之和，可能拆成两笔到账。
- 含"捷停车" → 停车费。含"抖音" → 忽略（不是商户收款）。
- 其余为对公或个人转账：对方户名可能是商户公司名，也可能是店主个人（如"李栋""刘鑫"），备注可能写费项（"飞科5-6月租金""潮正和水费"）。

## 认领规则（引擎执行，模型只解释）

1. 精确：对方户名去掉公司后缀后等于商户名或品牌，或付款人映射表命中 → 自动认领。
2. 备注解析：从备注抽出商户、费项、期间再模糊匹配 → 高置信自动认领，否则给建议。
3. 金额匹配：金额等于某商户某期未收 ±1 元 → 只给建议，进待认领。
4. 都不命中 → 待认领，先挂暂收款。用户在卡片或对话里确认后写入分配，并记住付款人。

拆分：上报或备注有明细按明细；否则按该商户未收顺序 租金 > 经营服务费 > 推广费 > 电费 > 水费 逐项冲抵，余额挂暂收款。跨月按自然月、按天数比例分摊。

## 平台明细到商户

- 微信 706 订单的商品名形如 `商户:趣捞鱼-3033 电表:1`，直接给出商户与铺位，费项为电费。
- 微信 380 全部是停车费，不拆到商户。
- POS 大多数无付款附言，需要运营部上报（钉钉或网页）或人工认领；有附言的按附言解析。

## 术语

运营部 = 收钱的一线；登记 = 贺部长在收入日报表台账里记一行；做账 = 华新玉在金蝶里录凭证；应收表 = 运营部维护的租费/水电费应收明细表；暂收款 = 认不出归属时先挂的科目。

## 工具使用顺序

1. `finance_status` 看数据库状态。
2. `finance_import` 导入应收表（主数据）、建行流水、微信/POS 对账单、充值记录、台账、凭证。
3. `finance_claim` 运行认领、列出待认领、确认、记住付款人。
4. `finance_daily_report` / `finance_voucher` 生成、导出、比对。
5. `finance_query` 回答欠费与收款问题。
