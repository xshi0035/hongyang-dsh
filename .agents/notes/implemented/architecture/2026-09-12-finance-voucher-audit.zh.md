# Agent Note: 财务凭证审计边界

Status: implemented

[English](2026-09-12-finance-voucher-audit.md) | 中文

## Problem

收款小计相等时费项分配仍可能不同。将这类配对认定为完全一致，会掩盖凭证科目与税额错误。显式指定账期的拆分也可能关联历史应收，导出时各金额列的单位必须一致。

## Decision

财务 provider 在台账行配对后比较每个费项金额，包括合并台账行形成的配对。费项差异使用现有金额差异结果，并说明具体费项。显式拆分日期约束应收关联。凭证生成使用已确认税率科目表，工作簿金额列统一为元。合成数据的 provider 测试覆盖组合收款到凭证、费项差异、账期关联和工作簿数值。

## Alternatives considered

- 仅按小计验收会漏掉费项分配错误，不能满足凭证验证。
- 将客户参考凭证直接用于生成会掩盖上游认领错误。参考数据不参与自动生成，有记录的人工纠正与自动认领验收分开。
- 仅凭金额匹配 POS 订单不能证明商户归属，因此未识别订单仍保持未解决。

## Consequences

费项错误暴露后，重新导入样本的匹配数可能下降。纠正有证据的本地登记需要数据库备份和本地证据记录，客户数据不进入 Git。纠正后限定业务范围内的凭证转换通过，不代表全日记账范围或自动认领通过。付款人身份歧义、简略费项备注、未确认科目和手续费前后金额的结算口径仍需业务复核。
