# Agent Note: 钉钉付款由工作台批准入账

Status: implemented

[English](2026-09-15-hongyang-workbench-approval.md) | 中文

## Problem

钉钉确认商户的同时也会入账，但财务人员需要在工作台单独作出决定。旧付款截图中的时间还可能让待审核单被工作台的日期筛选隐藏。

## Decision

钉钉确认将原始证据和选中商户提交到持久队列。稳定的草稿 id 保证桥接库与财务库之间重试的幂等性。只有经认证的工作台审核路由调用审批 provider。待审核单跨日期展示，不计入财务合计。批准重新校验证据，并在同一 SQLite 事务中保存流水、分摊、终态和网页审核记录。驳回只保存终态和日志，不入账。重复决定返回已有结果，相反决定则失败。

财务数据库以事务将已知的第 2 版升级到第 3 版，保留已有财务记录。审批事务内的嵌套 provider 写入使用保存点。每份存储只有一个 Stream 实例持有，启动时重新开放中断的卡片处理；已提交卡片的后续点击返回已保存结果。面板在打开和获得焦点时刷新。

非空的精确交易单号用于查找已登记的钉钉付款，或使用该单号的第一条待审核单。预览提前提示；提交和批准在写事务内重新检查。旧的重复队列记录仍可见，展示警告并禁用批准按钮；服务端以 `DUPLICATE_PAYMENT` 拒绝批准。最先提交的待审核单仍可批准。已驳回单据允许更正后重新提交；缺少单号不意味着重复。相同金额和商户不足以作为拒绝付款的依据。

驳回仅针对一条提交申请，不撤销同单号的另一条登记。重复提示分别说明最近的申请已驳回和原登记仍有效。时间采用财务时区下的原登记审核时间，缺失时使用分摊创建时间，不用截图付款时间代替。无法确定原登记时间时省略该字段。

## Alternatives considered

创建临时财务流水会把未经批准的款项混入记账合计。内存收件箱会在重启时丢失提交。独立持久队列保留证据，并以工作台作为审批边界。

## Consequences

Provider 测试验证提交和驳回的财务零写入、持久化、跨日期展示、相同决定重放、冲突决定、重新校验、迁移及审核日志失败后的回滚。Loader 图片卡片组合固定用户可见的提交文案，并推迟到批准后才入账。浏览器验收使用隔离库中明确标记的模拟付款，验证经认证路由及渲染列表。桥接层不生成 Session 转录；包内卡片预期文件记录产品输出。审批并不完成与导入银行流水的核对，也不证明最终流程的手机端到端验收通过。
